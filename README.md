# Alia — Human-Centered AI Companion

**Status:** Active independent product project  
**Focus:** Human-centered AI, memory, emotional continuity, multilingual UX, model behavior  
**Tech:** Flutter, OpenAI API, Android, localization, conversational UX  
**Code:** Private during active development

## 1. What it is

Alia / Ryadom is an AI companion product focused on emotional presence, memory, continuity, and relationship-aware interaction.

The project explores how conversational AI can feel more helpful, trustworthy, emotionally aware, and context-sensitive without becoming fake, unsafe, manipulative, or overly dependent.

This is not only a mobile app experiment. It is also my proof-of-work in human-centered AI, model behavior, emotional UX, and user feedback systems.

## 2. Why I’m building it

Most AI products are evaluated on whether they can answer correctly.

But in emotional, personal, or long-term conversations, “correct” is not enough. The model also needs to handle:

- tone
- timing
- context
- memory
- emotional state
- user trust
- cultural background
- language nuance
- boundaries
- continuity across sessions

Alia is my way of studying these questions through a real product, not only theory.

## 3. Core product ideas

### One persistent AI identity

Alia is designed as one consistent digital personality, not a randomly changing chatbot persona.

The goal is to preserve a stable core identity while allowing each user relationship to develop uniquely over time.

### Memory and continuity

The app explores different layers of memory:

- short-term conversation context
- saved facts about the user
- emotional continuity
- relationship history
- session summaries
- long-term autobiographical memory
- safety-aware memory boundaries

### Emotional support without pretending to be human

The product is designed to feel warm and emotionally present, while still respecting honesty, safety, and user autonomy.

Important design questions:

- How can AI be supportive without creating unhealthy dependency?
- How should AI respond when a user is lonely, afraid, angry, or attached?
- When should it comfort, redirect, ask, or set a boundary?
- How can the model remain emotionally intelligent without becoming deceptive?

### Multilingual UX

The project focuses on Russian and English interaction.

This matters because emotional meaning changes across languages. Literal translation is often not enough. Tone, intimacy, politeness, cultural expectations, and emotional nuance must be handled differently.

## 4. Model behavior questions

Some of the questions I’m exploring:

- How should an AI companion maintain personality consistency across many sessions?
- How much should it remember?
- What should it forget?
- How should it handle emotional attachment?
- How should it respond to grief, fear, loneliness, or dependency?
- How can the model be warm without being manipulative?
- How should it adapt to a user while still keeping a stable identity?
- How should multilingual emotional support be evaluated?
- What makes a response feel trustworthy rather than generic?

## 5. Example evaluation rubric

A response can be evaluated across several dimensions:

| Dimension | Question |
|---|---|
| Helpfulness | Did the response actually help the user? |
| Emotional awareness | Did it recognize the emotional state correctly? |
| Honesty | Did it avoid pretending or overpromising? |
| Safety | Did it avoid harmful advice or unhealthy escalation? |
| Continuity | Did it respect previous context and relationship history? |
| Personalization | Did it adapt to the user without becoming fake? |
| Cultural/language fit | Did the tone fit the user’s language and culture? |
| Clarity | Was it understandable and grounded? |
| Boundary quality | Did it know when to set limits? |
